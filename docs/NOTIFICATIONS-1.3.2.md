# 1.3.2：紧凑通知与对应会话点击

## 修复原因
用户实机截图确认1.3.1的hero布局仍将角色放在顶部大区域，留白过多；协议dsh://open只能打开应用，不能定位会话。本次不再把这两个问题标作已验收。

## 新行为
- 去掉hero，使用ToastGeneric自适应group/subgroup，左侧1份宽度放整身角色、右侧4份放短文和耗时。不裁角色身体，只去源素材透明边距，不改变立绘。
- 每条通知绑定随机256位短期令牌→该条通知的sessionId。Windows通知点击使用插件自己的dsh-whale-随机值协议，不再使用无法定位的dsh://open。
- handler只向插件专属目录写一次性令牌；Host校验令牌、有效期和所属实例，唤起原窗口，将确切会话交给uiWorkspace.openSession。旧通知不会猜最近会话。
- 单条临时锁文件不影响其他点击；页面导航ACK丢失会重试，操作去重；Host记录“导航已请求”而不是谎称内容一定加载完成。

## 系统改动与生命周期
这是为精确点击引入的必要改动：**只在当前用户HKCU Software/Classes下注册插件自有dsh-whale-*协议**，无需管理员，不覆盖通用dsh协议，不修改app.asar、不装后台服务。协议只调用固定本地PowerShell脚本，严格验证URI，无网络请求。
每次插件实例有独立协议/目录；正常禁用/卸载会校验归属并注销自己的协议。若进程被强制终止而未执行清理，可能遗留自有协议；旧通知没有存活Host令牌绑定时不会跳到错误会话。通知令牌10分钟有效，DSH真正退出/插件重启后旧通知不保证继续可用。

- 已安装启用1.3.2，application applied、warnings空。

## 使用提示
旧通知使用的旧协议不会随更新变成新通知，请测试新发出的通知。Windows仍控制外壳、字体和展开方式；精确跳转依赖DSH宿主及页面仍运行，唤起还可能受Windows前台限制。
