# 小鲸哨 2.1.0 · 验收记录

## 本轮范围

2.1.0 在 2.0.0 可靠性基础上补齐雷达信息与多窗口行为，不改形象：

1. 每个任务显示**工作区名**，并把运行中的**子代理个数**聚合到主任务行；子代理不再各自成为一行或一条提醒；
2. **presence 按窗口记录**：任一窗口可见且聚焦即视为前台，隐藏窗口不能覆盖聚焦窗口；
3. **长任务提醒**可选开启，同一轮超过 15 分钟只提醒一次，子代理不提醒；
4. 导航成功/失败回传 `diagnostic` 轨迹，面板与通知不再共用“未知失败”；
5. 设置写入统一提示，测试通知与业务统计隔离（2.0 已建立，本轮回归覆盖）；
6. 新增 `scripts/verify-release.mjs`，把版本、入口、导出、`index.js`、`host.js`、文档与素材清单绑成一道发布门禁。

未修改 DSH 核心或安装包。

## 自动化

`node check.mjs` → **158 tests / 158 pass / 0 fail**，随后发布门禁通过：

```
PASS release 2.1.0: entry, exports, files, index, host, docs and artwork agree
```

本轮新增门禁：

- 子会话只聚合到父行，`children` 只统计活动中的子会话；子会话不产生通知；
- 任一聚焦窗口压制原生通知，隐藏窗口不能清除该状态；
- 长任务默认关闭、开启后每轮一次、子代理不触发；
- `diagnostic` 只接受两个导航阶段，并写入 delivery 轨迹；
- 终态回执一小时后清理，pending 通知不会被误删；
- 客户端与宿主使用同一套纯文本规则（逐字符对账，含 Markdown、链接、控制字符、超长截断）；
- 工作计划区、子任务数、长任务开关、导航诊断在客户端真实存在；
- 版本一致性：只剩一个 `release-2.1.0.js`，导出、`index.js`、host 版本、文档、WebP 清单必须一致。

## 结论

2.1.0 把雷达从“有哪些任务”推进到“任务在哪个工作区、有没有子任务在跑、开了多个窗口时该不该提醒”，并把导航结果纳入可追溯的轨迹；同时用发布门禁消除了版本、文档、入口漂移。剩余真机项（双实例、520px、深色观感、系统横幅）保持未验证状态。素材来源与权利见[素材说明](<ARTWORK.md>)与[署名](<../ATTRIBUTION.md>)。
