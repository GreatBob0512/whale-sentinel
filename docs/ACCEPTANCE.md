# 小鲸哨 2.0.0 · 验收记录

## 本轮范围

2.0.0 是**可靠性版本**，不改形象、不改面板信息结构。改动集中在五处：

1. 原生提醒投递改为显式状态机：失败回队重试，最多 3 次，终态如实标记为失败；
2. 点击桥未就绪时降级为“仅提醒”，不再静默丢弃，也不猜测会话；
3. 协议按 profile 固定共享，多实例不再互相删除；卸载时按实例心跳决定是否注销；
4. 设置保存修复（成功不再报错、失败重试、不被旧快照覆盖），损坏偏好备份并恢复默认；
5. 导航与轮询解耦，导航失败不再误报“后台断线”；发布包补齐展开态 WebP；窄屏与深色偏好适配。

未修改 DSH 核心或安装包。

## 自动化

`node check.mjs` → **146 tests / 146 pass / 0 fail**，外加语法、分发表、图标与 PNG/WebP 校验。

本轮新增门禁：

- 原生失败后必须回队并重试，3 次后为 `native-failed`，不能记成成功；
- 点击桥未就绪时仍要发出提醒，且必须带 `noNavigation`、不得带 `activationUri`；
- 桥已就绪但签发失败时，降级只能发一次，不能排成重复重试；
- 一条通知抛错不能中断同一轮其他通知；
- 面板行与通知必须选中同一个待处理请求；
- 测试通知不得进入历史、不得改变“已完成”统计；
- 统计必须区分活动会话与结果事件；
- 偏好文件损坏时保留备份、用安全默认值启动；
- 同一 profile 协议稳定一致，不同 profile 互不相同；
- 共享 spool 目录不得消费或删除其他实例的点击令牌；
- Windows 启动器必须 UTF-16 编码，清理旧协议必须证明其目录已不存在；
- 窄屏规则必须收起角色而不是裁掉面板；深色偏好必须换底色；
- 分发清单必须包含 `assets/*.webp` 与 `release-2.0.0.js`。

## Windows 点击入口实测

- 注册表命令为 `wscript.exe //B //Nologo "<spool>\activate.vbs" "%1"`；
- `activate.vbs` 为 UTF-16 LE + BOM（1610 字节，首字节 `FF FE`），中文用户目录不会被写成 `?`；
- 直接以 `wscript //B` 调用该启动器并传入符合格式的 URI，**确实在 spool 目录写出 `<token>.click`，内容与 token 完全一致**，随后已删除该测试文件。

## 边界

- 未做**真实横幅点击**的人工验收：本次只验证了协议入口能把点击写成可消费的点击文件，以及页面侧的认领/导航逻辑由自动化用例覆盖；系统横幅外观与真实点击仍受 Windows 通知设置影响。
- **双实例并行**只做了单元级验证（共享协议、未知令牌不消费、心跳决定注销），没有同时启动两个 DSH 真机点击验证。
- 窄屏规则**只验证了样式表存在**，探针运行在 1707px 宽视口，未在 520px 以下实机测量裁切。
- 深色偏好只验证了规则存在，未在深色系统主题下做人工观感确认。
- 以上未做项不得表述为“已验收通过”。

## 结论

2.0.0 解决了 1.x 中“提醒可能被静默丢弃、多实例互相破坏点击、设置报假错、统计口径混乱、发布包缺素材”这几类确定问题；剩余的真机项（双实例、窄屏、深色观感、系统横幅）列为后续验证。素材来源与权利见[素材说明](<ARTWORK.md>)与[署名](<../ATTRIBUTION.md>)。
